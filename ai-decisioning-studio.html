✦ Product design case study

AI Decisioning Studio

Scroll
RoleSenior Product Designer
CompanyOptimove
DisciplineUX · UI · Design System
TeamProduct Management · Engineering · Data Science

Four AI agents, one shared goal, and a set of screens that had to make handing over control feel reversible.

Optimove's decisioning agents already worked. They just worked in silos, each optimizing its own thing with no shared measure of whether any of it helped. Optimization Power groups campaigns under one Strategy with a single KPI goal. This is the interface work behind that idea: what each screen is for, the flow a marketer actually walks, and the places where the flow ran out of screen.

What changed

Agents pulling in one direction

Journey Decisioning, Offer Decisioning and Send Time Optimization each optimized their own slice of a campaign and reported their own numbers. Nothing added them up. Grouping campaigns under one Strategy with a shared KPI goal was the product idea. Giving it a surface was the design problem.

01

One goal, four agents

The moment agents share a KPI, a marketer needs to see their combined effect, not four separate reports. That meant designing a place where coverage and impact across a whole Strategy could be read in one look.

02

A hub, not four errands

Switching an agent on lived in whichever product area happened to own it. Activation had to become one decision made in one place, which is what the Campaign Optimization hub is for.

03

Reversible before automatic

Marketers do not hand a live audience to a model they cannot inspect. Every screen had to answer three questions: what is it changing, what is it doing now, and how do I stop it.

The screen

Campaign Optimization

The hub is one card per agent, sitting on the campaign it optimizes. A card carries the agent's state, what it is worth, and the way in. It is the only screen in the feature a marketer is guaranteed to visit, so it does the explaining the others do not have room for.

What this screen is for

Answering "is anything optimizing this campaign, and should it be" without opening anything. Everything else in the feature is reachable from here.

What the flow showed

One hub, four different ways in

Drawing activation for all four agents on one page made the real state of the feature obvious. Two agents had no setup screen at all. Send Time Optimization had one, but it lived on its own page and was never connected to the hub, so the card promised a route that did not exist.

The consequence

A card with only one state

The card was designed for the happy path and nothing else. There was no Ineligible state for a campaign the agent cannot run on, no Learning state while it gathers signal, and no Paused state after a failure. A card that can only say Active cannot be trusted to say anything.

The decisioning agents

Four models, one description pattern

Each agent is a different model doing a genuinely different job, and a marketer meets them all on the same hub. They share a typographic family and a fixed "an AI agent that..." sentence so that the boundary of each one is legible on first contact, before anybody reads the detail.

Journey Decisioning

An AI agent that decides which campaign wins when a customer qualifies for several on the same day.

It replaces the manual priority rules marketers used to maintain by hand, ranking overlapping journeys on predicted future value. The design problem was orchestration: showing which campaigns are competing and why one was chosen, without turning the screen into a rules editor.

Offer Decisioning

An AI agent that finds the right incentive per customer instead of the one that won on average.

Static A/B testing picks a single winner and gives everyone the same discount, which quietly costs margin on customers who would have converted for less. The screens had to make the margin argument visible, because that is the part a marketer has to defend internally.

Send Time Optimization

An AI agent that predicts when each customer is most likely to be paying attention.

The simplest of the four to explain and the most awkward to reach. Its setup already existed on a separate page built before the hub, so the card on the hub pointed at a route that had never been wired to it. Naming that gap was most of the contribution here.

Content Decisioning

An AI agent that writes and tests copy variations, then keeps the one that performs.

The only agent designed end to end, and the one the rest of this page follows. It is also the hardest to hand over, because it changes words a marketer wrote. The next three flows are all Content Decisioning: how it is set up, what it does once live, and what happens after.

Setup

Four questions and a review

Setup is a modal, not a page, because it belongs to the card that opened it. It asks which templates, what to write, how many variations, and in what tone. Then it shows every generated variation before anything is applied, since the review is the last point where a person is still in charge.

What this screen is for

Turning a vague instruction into something specific enough for the model to act on, while never letting generated copy reach a customer without a human seeing it first.

The design

The path forks once

The wizard branches on a single question: how many templates the campaign has. One template goes straight to the content questions, several adds a selection step first where the AI pre-selects everything and the marketer removes what should not be touched. Defaulting to all and letting people subtract is faster than an empty list, and it teaches the scope of the change.

What the flow showed

The happy path was the only path

Drawing it revealed that almost everything hanging off the spine was undrawn: no ineligible state, no field validation, no generating state, no failure handling if the model returns nothing. There was also a live design bug. The variation count offered "1", and a test with one arm is not a test.

Optimization

What the agent actually does

Once applied, the agent splits the audience across the variations, watches which one performs, and promotes the winner. That is the whole promise of the feature, and it is the part of the product with the least interface attached to it.

The gap

Nobody had defined the split

How the audience divides across arms, how much signal counts as enough, and what the card shows while it is still learning were all unspecified. The feature was shipping a test whose rules had never been written down, which meant no two people in the room were describing the same behaviour.

The harder problem

Three agents move the same number

Content Decisioning measures itself on open and click rate. So does Send Time Optimization. So do Offer and Journey Decisioning, indirectly. Run them together, as the Strategy explicitly encourages, and no agent can honestly claim the lift it reports. Drawing the flows is what surfaced this, and it is a measurement question the UI cannot solve on its own.

Live management

The screen that was missing

After a marketer applies the agent, the interface stops. The Active card is a read-only tile with two numbers on it. Every question a person has once something is live and touching real customers has no screen behind it.

1

Built state

Active, showing two benefit figures. That is the entire post-activation interface.

6

Controls with no screen

See per-variation results, reopen the setup, add or remove variations, pause, turn off and revert, and an audit trail of who applied what.

2

Unanswered questions

What happens to learning if the setup is edited mid-test, and what happens to customers who already received a variation that gets reverted.

  • Why this is the finding, not a footnote. The third principle of the feature was that automation has to be reversible. The flow shows it is not. A marketer can switch the agent on in four clicks and then has no supported way to pause it, inspect it, or take it back.
  • Why the diagrams look like this. Solid outlines are screens that exist, dashed outlines are screens that do not. Drawing both in the same picture is the point. A flow that only documents what was built cannot show you what is missing, and what was missing here was most of the second half.
